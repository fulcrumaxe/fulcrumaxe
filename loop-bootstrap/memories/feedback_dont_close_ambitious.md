Stop closing Discussions as "out of scope." When a proposal is ambitious (like a SaaS platform), scope it down into a practical first step — don't reject it.

**Why:** The user explicitly pushed back on the PM closing #94 and #96. The autonomous team's mission includes evolving itself, which could mean building new infrastructure. "Self-improvement is the product" doesn't mean "only improve existing code."

**How to apply:** When the PM encounters an ambitious Discussion, it should:
1. Extract the smallest useful kernel from the proposal
2. Create a practical first-step spec (like we did with Epic #58's 5 layers)
3. NEVER close a Discussion as "out of scope" — always find something actionable
4. Let the user decide what's out of scope, not the PM
